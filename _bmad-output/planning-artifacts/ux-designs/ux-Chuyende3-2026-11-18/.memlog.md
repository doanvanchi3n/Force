- (event) User yêu cầu tạo Design System và Prototypes dựa trên bộ tài liệu BMAD đã sinh, kết hợp ui-ux-pro-max. Phạm vi nguồn đã được user chỉ định là bộ discovery 16/11; đây là đầu ra thiết kế để xem xét, không phải PRD hay stack đã duyệt.
- (event) Đã hỏi định hướng thị giác/brand và lựa chọn Markdown + HTML tương tác hoặc chỉ Markdown. Chưa có câu trả lời tại thời điểm khởi tạo. Không có UX workspace trước đó. Activation hooks, persistent facts, external sources đều rỗng.
- (assumption) Chưa có trả lời định hướng thị giác sau thời gian chờ. Tiến hành bản nháp reviewable, không coi im lặng là chấp thuận. Bố cục web responsive, tiếng Việt, desktop BTC và mobile sinh viên; không chọn framework hay stack ứng dụng. Dự kiến Markdown + prototype HTML cục bộ có tương tác để minh họa; có thể điều chỉnh theo trả lời sau.
- (assumption) Hai luồng ứng viên từ discovery: sinh viên xem sự kiện → đăng ký → xác nhận/tra cứu → hủy; BTC danh sách → check-in/ngoại lệ → báo cáo. Không thu dữ liệu thật, không gửi email thật, không đăng nhập thật, QR/camera và mạng chỉ mô phỏng. Không phê duyệt/bác bỏ portal; prototype dùng tác vụ tra cứu không tài khoản như phương án để thử.
- (event) Tra cứu ui-ux-pro-max: event registration dashboard/product (Event Management phù hợp; Wedding off-topic loại bỏ; hiệu ứng motion/glass chỉ là gợi ý không chọn); error summary validation/ux và keyboard focus modal/ux hỗ trợ lỗi gắn trường, focus hiển thị và thông báo trạng thái. Đọc W3C contrast minimum, target size minimum, APG modal để đối chiếu mục tiêu accessibility.
- (assumption) Visual candidate V1, not user-approved: Force event workspace, light theme; navy text/sidebar, blue primary and restrained lime highlight for event illustration. Minimal grid/type style is a local design proposal after ui-ux-pro-max Minimalism & Swiss and Calendar/Scheduling blue candidate; not VSC branding. No glass, gradient, decorative animation, stock photo or logo impersonation. System font stack for offline Vietnamese rendering.

- (assumption) Prototype scope to illustrate, not approved product: S01 event detail, S02 registration form, S03 confirmation/status with cancel dialog, S04 lookup by private demo code, S05 organizer attendee list with search/status filters, S06 check-in lookup/detail/result with duplicate/cancelled/not-found/offline/permission states, S07 summary/report export preview. S08 component gallery is design-tool page, not product requirement. No event discovery catalogue, event creation, account login, payments or real email integration in this prototype.
- (assumption) Layout proposal: student detail two columns desktop with typographic event artwork at left, agenda/venue and sticky-free registration summary right; form/status centered narrow with event context. Organizer desktop sidebar, event header, summary counters, toolbar and participant table; mobile stacked header/nav and participant cards. Check-in split search/list and selected-person confirmation; report counts/table. Consistent header, breadcrumbs, badges with words and clear main CTA. Prototype toolbar above app changes roles, toggles network/permission demo and resets data; explicitly not production authentication.
- (assumption) Behavior prototype rules: fictional event Workshop: Tự tin thuyết trình, 26/11/2026 17:30–19:00 at Phòng sinh hoạt CLB (minh họa); no claim real event. Register name+email only, trim and validate; no MSSV until justified. Duplicate normalized email returns existing-state guidance without extra record. Demo codes FORCE-001 etc are local fixture, NOT real secure tokens. Lookup by code demonstrates private link concept; no public student roster. Registration immediate only as prototype assumption; actual approval rules TBD. Register active registered; check-in can transition registered→checked only once; cancellation registered→cancelled with confirmation; checked record cannot be cancelled; cancelled cannot check in. Undo check-in via confirmation and required reason; no server audit claim. Offline/permission-denied demo blocks changes and retains displayed data. All state in memory; reload/reset restores fixtures; no localStorage or network.
- (assumption) Content rules: Vietnamese concise functional labels, status Đã đăng ký/Đã tham dự/Đã hủy. Never show false sent-email/server-sync/camera success. Demo scenarios prominent outside product flow; inside status relevant plain guidance. Fictional named protagonists Lan for Persona B and Minh for Persona A only to narrate testing, not real research people. UJ-01 registration/confirmation; UJ-02 lookup/cancel; UJ-03 check-in and exceptions; UJ-04 report/CSV. Each gets numbered steps, climax and failure paths, traced to six source journey stages and P/RD-A IDs.
- (assumption) Components shared names in both spines: AppShell, EventPanel, Button, FormField, ErrorSummary, StatusBadge, Notice, FilterBar, ParticipantList, StatCard, ConfirmationDialog, StatusTimeline, EmptyState, ReportTable, DemoToolbar. Components visual and behavior rows must match. Accessibility targets 4.5:1 normal text, 3:1 large text/control indicators, visible focus and semantic labels; native dialog focus trap/Escape/return; live results without focus theft, focus h1 after route navigation, reduced motion. Target44CSSpx is project proposal exceeding WCAG22 minimum24 with exceptions. No claim full conformance.

Error summary validation and focus modal support field-linked errors and visible focus.
